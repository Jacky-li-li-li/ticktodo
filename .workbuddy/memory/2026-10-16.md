## 第二轮修正（用户反馈后）

- **多 session 元数据不进 Tick**：session 规范（有什么/叫什么/cwd/活跃/是否存在）归 ai 工具，
  adapter 是权威源（`listSessions` / `describeSession`）；Tick 只持久化 `Todo.bindings[]` + `primarySessionId`。
  原设想的 `CliSessionMeta` 镜像表作废（避免改名/删除后腐烂）。
- **凭据复用 pi**：面板 Chat 用 `ExtensionContext.modelRegistry` 解析 key，就绪性走
  `pi auth check --provider <p> --json`；Tick 不持有任何 Key，safeStorage 需求取消。
  实测 `pi auth check --provider magpie --json` → `invalid`（默认 provider 凭据当前不可用，首屏必须探测）。
- **Q1 结论（读源码后推翻）**：`pi "消息"` 是**立即发送**（main.js:734/783 → interactive-mode.js:894
  `session.prompt()`），pi 无"仅预填"模式。用户口头说的"预填"与源码相反，已写入待定项让其确认。

## 第三轮：读 pi/pi-durable 源码结案 Q2–Q5

- Q2 `--name` 可见 ✅：`session-selector.js:390` `displayText = session.name ?? firstMessage`；
  name 存于 `session_info` 行（session-manager.js:913-921），**不在 header** → 拿 name 要全量读文件。
- Q3 pi-durable 可指定目录 ✅：1.3.0 `openNodeJsonlStorage(dir)` / `openNodeSqliteStorage(path)`；本机未安装。
- Q4 本地扩展不必 `-e` ✅：`~/.pi/agent/extensions/` 自动发现（`package-manager.js:2012`），或 `pi install`。
- Q5 pi 不做 git 根归并 ✅：`session-manager.js:293` 一个 cwd 一个目录；目录名编码有损（`/\` `:` → `-`）。
- 陷阱：`getDefaultSessionDir()` 会 mkdirSync，spawn 时 cwd 传错会凭空造项目目录。

## 第四轮决策

- **投递取向已定：默认剪贴板（B），设置里可切自动发送（A）**。pi 无"仅预填"模式。
- **免选项目直接执行**：cwd 不可省（pi 无 `--cwd`），改为定义默认值优先级——
  ① 已绑定 session 的 cwd（resume，最优）② 用户显式选 ③ 默认项目=最近使用，无记录→home
  ④ 设置项「每次必问」。主按钮必须显示项目名（cwd 错了 AI 会在错目录干活 + mkdirSync 造垃圾目录）。
- 新增 F4-a 小节，验收加 4.1，开放问题加 Q7（是否跟随前台 Finder 目录，建议延后）。

## 第五轮决策：项目选型改为「选填」（D9）

- 拍板：**项目选填**，与"内容/描述选填"同级。注意区分：用户不必做**选择动作**，但 cwd 不可缺省。
- 默认 cwd 优先级（`CwdResolver`，main 侧纯函数）：① 已绑定 session 的 cwd（adapter 权威值）
  ② `Todo.lastProjectPath`（用户显式选过一次后记住，**新增**）③ 最近使用项目，stale 则降级
  ④ home ⑤ 设置项「项目每次必问」= 开时跳过 ②③。
- `lastProjectPath` 记的是用户意图不是工具状态，故不违反"不镜像 session 元数据"原则（session 被删仍有效）。
- 首版只留两个设置项：投递方式（默认剪贴板 B）、项目每次必问（默认关）。→ PRD 新增 F4-b。
- 风险四条：默认值必须可见（按钮显项目名）+ 默认 B 保留人工审阅（与选填互补，非二选一）
  + stale 自动降级并提示 + 冷启动不阻塞 UI。
- 项目一变选填，F3 项目索引升为主路径地基 → Q7 升 P1；新增 Q8（ProjectIndex 冷启动：后台扫 + 缓存首帧）。

## 第六轮：多 AI 工具下的项目索引分层

- **核心：项目是工具无关概念，目录做主键，工具只做证据标签**（主键不能是 `(toolId, path)`）。
- 三层：adapter 只吐 `ProjectSource`（原始 cwd + 计数，不归并）→ `ai/core.mergeProjects()` 纯函数
  做归一化/git 根上卷/按路径合并/排序 → `main.ProjectIndexService` 负责调度 + 分段缓存 + IPC。
- 三处现在就要改（否则第二工具接入时返工）：
  ① `source: 'pi'|'user'` 单值 → `tools: string[]` + `pinned`；
  ② `Todo.lastProjectPath` → `lastLaunch { toolId, projectPath }`（只记目录，换工具就白选）；
  ③ CwdResolver 必须按 `binding.toolId` 取 adapter，不能直接拿 sessionId 问 pi。
- **排序用 Tick 自己的时钟**：`lastLaunchedAt`（拉起时回写，P0 就要写）> adapter `lastUsedAt` > 目录 mtime。
  工具侧时间口径不同且会偏斜，是唯一可对齐的跨工具时钟。
- 归并不留到 P2：P0 就按工具无关实现，演进表 P2 改为"只加 adapter，不动 core/UI"。
- `canonicalPath` 集中在 core：realpath、`/private/var`、大小写、trailing slash、worktree（.git 为文件不上卷）。
- 类型留口：`ProjectRef = {kind:'dir'} | {kind:'remote'}`，别把项目写死成目录。
- 新增 Q9（git 根上卷默认开是否合适）。
